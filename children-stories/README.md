# 一句话儿童睡前故事 · 小程序需求梳理

暂定名称：**小故事的睡前时光**（名称待定，不影响开发）

一句话产品：**家长说一句，得到一个能听、能看、能跟读的原创睡前绘本故事。**

> 本文档只梳理需求与范围。技术选型细节在 [`docs/接口与数据.md`](./docs/接口与数据.md)，页面细节在 [`docs/页面与交互.md`](./docs/页面与交互.md)，排期与提审在 [`docs/MVP排期.md`](./docs/MVP排期.md)。

---

## 1. 产品定位

| 维度 | 说明 |
|------|------|
| 一句话 | 把「今晚给孩子讲什么」这件事的成本降到 0 |
| 核心价值 | 家长的一句随想 → 一篇专属于自己孩子、篇幅刚好、能熄屏收听的原创故事 |
| 差异点 | ①输入是家长的话，不是公共故事库；②逐句高亮 + 童声慢速朗读，能跟读；③每次生成都有配图，是「一个人的绘本」；④按孩子累积成专属系列 |
| 竞品形态 | 叽里咕噜/凯叔类是**内容库**（孩子被动听别人的故事）；本产品是**生成器**（家长是编剧，孩子是主角） |
| 平台 | 微信小程序（原生）+ 自建 Java 后端 |

**为什么这个形态成立**：睡前故事的痛点不是「没故事听」，是「家长想讲的正是孩子今天遇到的事」——第一次分床、被小朋友抢玩具、怕打雷。公共库覆盖不到这种即时、私人、具体的需求，而这恰好是大模型最擅长的。

## 2. 目标用户（已定）

| 角色 | 是谁 | 干什么 |
|------|------|--------|
| **操作者** | 5-7 岁孩子的家长（25-40 岁，妈妈为主） | 输入一句话、选参数、点播放 |
| **听众** | 5-7 岁孩子 | 躺着听、看屏幕、跟着念 |
| 场景 | 20:30-21:30 卧室，关灯或暗光，家长单手操作 | 一次 5-8 分钟，播完孩子睡着 |

场景推导出的硬约束（这些是需求，不是建议）：

1. **暗光环境** → 默认暖色低亮度配色，禁高对比白底；亮度不能自适应拉满。
2. **家长单手 + 困** → 首页到开始播放 ≤ 3 次点击；生成后不弹任何需要决策的对话框。
3. **孩子要睡** → 必须有「播完自动停止」和定时停止；语速默认偏慢；无突然响亮的音效。
4. **熄屏还要继续放** → 必须用后台音频，否则屏幕一关故事就断（这是睡前场景的第一功能，不是增强项）。需 `app.json` 的 `requiredBackgroundModes: ["audio"]`，且**正式版要过审后才生效**；后台期间不能用 API 操纵播放，直接影响「定时停止」的设计（见 §6.5）。
5. **不能养成刷第二个** → 明确不做自动连播、不做无限下拉推荐。这不只是产品底线：《未成年人网络保护条例》第四十二条明确要求「建立健全防沉迷制度，**不得向未成年人提供诱导其沉迷的产品和服务**」→ 按**法定义务**实现，不做成可关掉的设置。

## 3. 核心链路

```
家长输入一句话
  → 输入内容安全审核（微信 msgSecCheck 类接口）
  → Prompt 编排（年龄档/时长/音色/寓意开关 → 结构化生成）
  → LLM 流式输出：标题 + 5-7 段（每段 60-90 字）+ 角色外形描述 + 结尾寓意
  → 输出内容安全审核
  → TTS 整篇合成：mp3 + 句级时间戳      ┐
  → 图像生成：每段一张（异步，首图优先）  ┘ 并行
  → 落库 + 音频/图片转存对象存储
  → 播放页：逐句高亮 + 熄屏连续播放
  → 收藏 / 换音色重播 / 再来一个
```

**并行策略（决定等待时长的关键）**：文字先出（用户看得见故事在生长）→ 音频就绪即刻**可播** → 图片逐张淡入。不允许「全好了才显示」——那会让首屏等 25 秒以上。

⚠️ 「可播」不等于「自动播」：微信《常见拒绝情形》**3.5.2** 原文禁止「视频、音乐、语音等多媒体的自动播放」→ 就绪后停在待点的播放键，**由家长点一次起播**（见 §10 第 13 条）。

**时长目标**：P50 首段文字可见 ≤ 4s；P50 可播 ≤ 12s；P90 可播 ≤ 25s；图片全部就位 ≤ 40s（不阻塞）。

## 4. 信息架构（双 Tab）

```
底部 Tab
┌────────────────┬────────────────┐
│     讲故事     │      我的      │
└────────────────┴────────────────┘

讲故事 = 首页（输入 + 最近）    我的 = 孩子档案 + 收藏 + 听过 + 设置
故事播放页从讲故事页推入（页面栈，非 Tab）
```

只两个 Tab 的理由：本产品是「一次性工具 + 轻留存」，Tab 越多首屏越不像「说一句就能开始」。

## 5. 功能模块

### 5.1 输入与参数（Must）

| 项 | 取值 | 默认 | 说明 |
|----|------|------|------|
| 一句话 | ≤ 40 字自由文本 | 必填 | 例：`小兔子第一次自己睡觉`、`乐乐怕打雷` |
| 主题兜底 | 8 个 chips（分床睡/第一天上幼儿园/被抢玩具/怕黑/牙齿掉了/输了很生气/奶奶生病了/交新朋友） | 点击填入输入框 | **必须有**：家长最常卡在「不知道写什么」。冷启动也靠它 |
| 时长 | 短 3 分钟(~250字) / 中 5 分钟(~450字) / 长 8 分钟(~700字) | **中** | 睡前默认 5 分钟 |
| 音色 | 温柔姐姐 / 故事爷爷 / 同龄小伙伴 | 温柔姐姐 | 3 个即可，多了选择成本高 |
| 结尾寓意 | 开 / 关 | 开 | 输出「一句话寓意」，不说道教 |
| 轻音乐 | 关 / 八音盒 / 雨声 / 白噪声 | 雨声 | 混音在服务端做（见 §6.4），不做则睡前氛围缺一半 |
| 孩子 | 选择已有小名或新建 | 第一个 | 影响称呼与系列计数 |

### 5.2 生成过程（Must）

分阶段进度文案（等 10-25s，文案要有温度）：`在想故事…` → `写下来啦，一段一段给你看` → `正在画插图` → `请来温柔姐姐念给你听`。支持取消；失败要能一键重试且**不重复扣额度**。

### 5.3 故事播放页（Must，核心页面）

标题 + 「给乐乐的第 5 个故事」；当前段绘本图；当前段文字逐句高亮（当前句放大 + 变色）；控制条：上一句 / 播放暂停 / 下一句、进度、语速 0.8/1.0/1.2、定时（播完停止/15/30 分钟）、收藏、再来一个。段随音频自动翻页，也可横滑手动翻。熄屏后台继续播放。

### 5.4 我的（Must）

孩子档案（小名/年龄档，**不采集真实姓名、生日、照片**）；收藏列表；听过（历史，按日期分组）；「给孩子起的系列」计数展示。

### 5.5 暂缓（Won't / Should 见 §8）

分享海报（你未选，列入第二版）、社区/评论、孩子录音复述打分、付费会员、英文故事、App/H5 端、**与故事角色对话（拟人化互动）**——最后这条不只是范围控制，它避开「向不满 14 周岁提供拟人化互动服务需监护人同意」的额外义务，见 §10 第 7 项。

## 6. 需求细化：这四条决定产品成不成功

### 6.1 故事质量契约（写进 Prompt 的验收标准）

5-7 岁睡前档的具体要求，可当测试用例用：

| 维度 | 契约 |
|------|------|
| 长度 | 全文 380-520 字；**5-7 段**；每段 60-90 字（一段 = 一屏 = 一张图 = 一次翻页） |
| 结构 | ①建立角色与场景 → ②③④小冲突/小发现（每段一个动作）→ ⑤温柔解决 → ⑥收尾 + 一句话寓意（可选） |
| 句长 | 平均 ≤ 18 字，单句 ≤ 25 字 |
| 词汇 | 不用生僻字、不用成语典故、不用抽象概念；可用拟声词（咚咚咚）与重复句式（找找，找找） |
| 角色 | 首段给出**外形锚点**（白色小兔子 / 左耳有个月牙斑 / 戴蓝色围巾），后续段配图必须一致（见 §6.3） |
| 情感安全 | **禁止**：恐吓、死亡、抛弃、暴力、尖锐噪音描述、离家出走未找回、陌生人为孩子开门。结尾必须安全感收束 |
| 禁止 | 真实品牌/动画 IP 角色（米老鼠/小猪佩奇一律不许出现）、宗教政治、医疗建议 |
| 主角代入 | 输入含孩子小名时，把小名设为「听故事的人」或旁白称呼，**不强行让动物叫孩子名字**（会诡异） |
| 时长 | 单段音频 8-20s；整篇 4-6 分钟（含音乐淡出） |

### 6.2 逐句高亮的技术契约（火山侧能力已核实）

- **数据**：火山 TTS v3 支持**逐字时间戳**（`with_timestamp`，返回 `utterances[].words[]`，单元是单字，时间是**秒**）。后端把它**派生成句级** `[{text, startMs, endMs}]`（每句取首字 `startTime`、末字 `endTime`，×1000 转 ms）再落库下发。
- **音频形态**：**整篇一条 mp3**。火山 v3 是 HTTP Chunked 流式返回**二进制**、不给 URL，所以后端必须做「聚合 chunk → 完整 mp3 → 混 BGM → 转存 OSS → 签名 URL」。小程序音频组件不能消费 chunked 二进制，这一层不能省。
- **高亮实现**：`onTimeUpdate`（250ms 节流）在句子数组上二分查找当前句，只 `setData({sentenceIndex})`；不做逐字动画。
- **必须做的兜底**：若时间戳缺失或分段合成后偏移不可信，按「句字数 ÷ 全文字数 × 总时长」估算，并在数据上标记来源，便于观测观感。这样**高亮功能不被供应商能力卡死**。
- ⚠️ 一个尚未量化的风险：v3 单次文本上限官方未明示，而旧接口是 **1024 字节**（450 个汉字约 1350 字节，已超）。若长档必须分段提交，**段间偏移累加算错就会让高亮从第二段开始错位**——这是写适配层时第一个要实测的点。

### 6.3 AI 配图（你选了，注意这是最贵的一条；能力已核实）

- 数量：每段 1 张，5-7 张 → 这是成本与等待时长的主要来源。
- **角色一致性有官方机制**（好消息）：方舟 Seedream 的 `image` 参数支持参考图，主体一致性由模型保证，上限 5.0 pro 10 张 / 4.0 14 张。做法：段 1 生成「定妆图」→ 转存 OSS → 作为段 2-6 的参考图。**不必只靠 prompt 复述外形**。
- 尺寸：宽高比范围 `[1/16, 16]`，3:4 竖版绘本页原生支持，无需裁切。
- 加载顺序：第 1 段图优先，其余并行 5 路、逐张淡入；文字与音频不等图。火山返回的是临时链接，**必须转存**。
- **兜底**：图失败或被审核拦截（`OutputImageSensitiveContentDetected`）时，改 prompt 重试 1 次，仍失败用风格化卡片（暖色底 + 段号 + 标题）占位，绝不阻塞播放。
- **成本旋钮**：Seedream 每张单价与耗时未取到。若核实后图片成本远高于「文字 + 语音」，首版降为「1 封面 + 2 张关键段 = 3 张」，中间段复用背景模板——这是我给你留的第一个砍成本的口子。

### 6.4 轻音乐混音

睡前氛围需要背景音。在服务端把 TTS 音频与短循环音乐轨混音（音量约 -18dB 且随故事结束淡出），产出单个 mp3；不在小程序端混（小程序无多轨混音能力，两个 audio 实例互斥会打架）。**若首版人力紧，此项可降为 Should**——这是我在你选的范围之外建议加的一条，成本很低。

### 6.5 熄屏播放与定时（官方原文已核实，含一条需求修正）

- `BackgroundAudioManager` 是**全局唯一**实例；`title` **必填**；支持 m4a/aac/mp3/wav（火山输出 mp3 ✓）。
- **必须在 `app.json` 配 `requiredBackgroundModes: ["audio"]`**，官方原文：「开发版和体验版上可以直接生效，**正式版还需通过审核**」→ 归入 M0 清单，不要等到 M3 才发现。
- ⚠️ 需求修正，官方原文：「小程序切入后台，如果音频处于播放状态，可以继续播放。**但是后台状态不能通过调用 API 操纵音频的播放状态**」。
  → **定时 15/30 分钟停止在熄屏后做不到**。睡前场景的正解是把「播完自动停止」做成默认且主推档位（故事 4-6 分钟，天然落在入睡窗口内结束）；15/30 分钟档明确标注「需保持本小程序在前台」。**不要为了这个功能加轮询唤醒保活**——API 层面就不允许。
- 单次后台音频的大小/时长上限**未找到官方原文**；按 32kbps mono 估 5 分钟 ≈ 726KB，真机验证即可（见 `docs/MVP排期.md` 验收项）。

## 7. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 首屏可交互 < 1.5s；音频起播 < 2s（已下载时）；`setData` 单次 < 200KB |
| 幂等 | 每次生成带 `requestId`（客户端 UUID），服务端唯一索引；重试同一 requestId 不重复扣额度、不重复合成 |
| 复用 | 音频按 `文本hash + 音色 + 语速` 唯一，命中直接返回旧 URL；收藏的故事永久保留 |
| 限流 | 每用户每日 N 次（建议免费 3 次）；单用户并发 1 篇；单 IP/新号异常高频拉黑 |
| 降级 | LLM 主备（两家模型，超时/失败切换）；TTS 失败 → 纯阅读模式（无高亮无音频）；图失败 → 占位卡；审核接口不可用 → **默认拒绝**并提示重试（宁可失败不可放行） |
| 成本可观测 | 每次生成记录 tokens/字符数/图片数/各家耗时/估算成本，可按日聚合 |
| 生命周期 | 未收藏的音频与图片 30 天后回收；收藏的不删 |
| 安全 | 供应商密钥只在后端；小程序端只拿业务 API；所有响应按用户鉴权，禁按 ID 遍历他人故事 |

## 8. MVP 范围（按你的选择锁定）

**Must（第一版）**

- [ ] 一句话输入 + 主题 chips 兜底 + 时长/音色/寓意开关
- [ ] 流式分段显示 + 分阶段进度 + 取消/重试
- [ ] 三重内容安全：输入 `msgSecCheck`（同步）+ 生成文本 `msgSecCheck`（同步）+ 生成图片 `mediaCheckAsync`（**异步复核，需实现微信事件回调端点**）
- [ ] 「内容由AI生成」显著标识（含「AI生成」四字原样，不可折叠）
- [ ] 火山 TTS 整篇音频 + 句级时间戳
- [ ] 播放页逐句高亮、自动翻页、横滑、语速、定时停止、**熄屏后台播放**
- [ ] AI 配图每段一张（角色一致性 + 异步加载 + 占位兜底）
- [ ] 微信登录、收藏、历史、孩子档案（小名）
- [ ] 每日额度限流与成本日志
- [ ] 隐私政策 + 用户协议 + 反馈入口

**Should（尽量带上）**：轻音乐混音；失败原因友好化文案；「同样参数再生成一篇」；音频进度拖动。

**Won't（明确不做）**：分享海报、社区/评论、孩子录音评分、付费/会员、英文故事、自动连播、H5/App 端、**真 AI 视频生成**（理由与替代路线见 §10 第 11 条）、**音频下载/导出**（一旦提供导出，《标识办法》第四条末句要求文件内自带显式标识，得把提示音做进 mp3——首版不做导出就不欠这笔）。

## 10. 剩余风险（域名与主体两项已消除；🔴 头号项已换成「音频类目落脚点」）
