# 视频形态评估

回答一个问题：**「如果还有视频生成呢」**——加视频到底加的是什么成本、触发什么新增证照、哪条路线可以现在写、哪条写了要扔。

结论先说：**首版不写真 AI 视频。想让画面「动」，走 §2 路线 B（对已有配图做程序化运镜），它几乎免费且不触发新增类目。**

---

## 1. 为什么「先开发、上架再验证」这条经验对视频不成立

上面三份文档里，合规项都可以按「开发期实现 + 提审期交材料」来排——类目材料、微信认证、后台音频正式版审核都是这样。视频不是。

| | 文本 / 图片 | **朗读音频** | 真 AI 视频 |
|---|---|---|---|
| 最坏结果 | 被要求补材料、改文案、延期提审 | 🔴 **同样可能「类目层面根本没有可提交的材料」**（深度合成无语音合成子项，见 §4 末与 `docs/MVP排期.md` §6.1） | **测通了也发不出去** |
| 代码是否作废 | 不作废，功能本身合法 | 不作废——**但可能上不了架** | 主体不变的前提下该类目不开放 → 功能作废 |
| 卡点性质 | 材料是否齐备（可争取） | 材料是否齐备 **+ 类目落脚点是否存在** | 主体资格是否够（**争取不到**） |
| 能否砍掉 | 能，但不是本体 | ❌ **砍掉就没有这个产品**（睡前共读的核心是「有人念」） | ✅ 能砍，砍了不影响主闭环 |

所以视频的正确排序是**先解决主体与类目，再写代码**，而不是反过来。

⚠️ **本轮核实把这张表改写了**：原先我把「音频」和「文本/图片」放在同一列，假定深度合成类目对口本产品。实际核到原文后，**音频与文本/图片不同列**——它和 Video 一样面临「落脚点不存在」的问题，只是它的后果更重，因为它砍不掉。**换句话说：真正需要开工前打电话的是音频，不是视频。**

## 2. 四条路线判定

| 路线 | 做法 | 单篇增量成本 | 新增证照/类目风险 | 判定 |
|------|------|-------------|-----------------|------|
| **A 不做** | 播放页仍是「文字高亮 + 静态配图淡入」 | 0 | 无 | ✅ **首版采用** |
| **B 程序化动效** | 后端 ffmpeg 对已有 Seedream 图做 Ken Burns（缓慢推拉/平移）+ 段间交叉淡入，输出 mp4 或直接前端 CSS 动画 | ≈0（自己服务器 CPU）；前端 CSS 方案连文件都不产 | **低**。不是 AI 生成内容 → 不新增 AIGC 标识义务、不新增算法备案要素 | ✅ **推荐的可选项**。睡前氛围收益明显 |
| **C 真 AI 视频 1-2 段** | 只对首段或片尾做一次 Seedance 生成（3-5s），当「动态封面」 | 3-5s 单段 **2.5-19 元**（见 §3） | **中-高**。形态上已是「视频节目」，见 §4 | ⚠️ 先通 §6 的两个电话，再决定写不写 |
| **D 全片 AI 视频** | 每段都生成视频，6 段 = 一段完整动画 | **24-112 元/篇** | **高**，且成本结构失控（是现在单篇成本的 100-400 倍） | ❌ 这是**另一个产品**，不是本产品的功能 |

**B 与 C 的区别不是「动多少」，是「谁生的画面」。** B 的像素全部来自已经过审核的 Seedream 静图，只是加了运镜；C 的每一帧都由视频模型新生成，必须重走审核、重挂 AIGC 标识，且直接落到 §4 的类目问题上。

## 3. 火山 Seedance 技术事实（已核）

| 项 | 事实 |
|----|------|
| 调用形态 | **异步任务**：`POST https://ark.cn-beijing.volces.com/api/v3/contents/generations/tasks` → 拿 task id → 轮询/回调 |
| 图生视频 | 支持 `content` 里带图并标 `role`：`first_frame` / `last_frame` / `reference_image` → **可直接复用现有 6 段配图作为首帧**，角色一致性不用重做 |
| 计费 | 按 token 计费。实测口径速记：Seedance 2.5 约 **7.56 元/5s（720p）**、**18.71 元/5s（1080p）**；2.0-mini 约 **2.48 元/5s（720p）** |
| 单篇推算 | 6 段 × 4-5s：mini/720p ≈ **24 元**，2.5/1080p ≈ **112 元** |
| 开通门槛 | 账户**余额 > 200 元**才能开通该能力 |
| 结果地址 | 官方返回的 URL **24 小时或 100 次下载后失效** → **必须转存自家 OSS**，和音频/图片同一套转存逻辑 |
| 耗时 | 十秒级到分钟级（按任务排队），远长于 TTS |

三条工程含义：

1. **状态机要加一档**（`SYNTHESIZING_VIDEO`），且它是全链路里唯一「供应商侧长任务 + 回调/轮询 + URL 会过期」的组合，超时与重试语义和 TTS/Seedream 都不同。
2. **等待体验不成立**。现有 P50 ≤12s / P90 ≤25s 的「可播」目标建立在「文字先出、音频就绪即**可**播」（起播仍需家长点一次，见拒绝情形 3.5.2）。视频任务会让首屏等待进入分钟级，睡前场景（孩子已经困了）对等待的容忍度是全线最低的。
3. **熔断要重设**。现在的日成本熔断按「图是成本大头」设计；一篇视频 24-112 元会把免费次数打到每天 1-2 篇，商业模型直接变。

## 4. 合规：视频为什么比图片重得多

| 点 | 事实 | 影响 |
|----|------|------|
| `深度合成` 下的 **AI 创作** 适用范围原文 | 措辞是「适用于提供**文本**深度合成技术（如：AI创作）等相关服务」 | 视频形态**不能假定**已被这张资质覆盖；平台极可能要求另挂类目 |
| 深度合成实际只有 **5 个子项**（拟人化互动 / AI问答 / AI换脸 / AI绘画 / AI创作，「三级分类」列全为 `/`） | 锚定的技术形态分别是 情感互动 / 文本 / **视频** / 图片 / 文本 | ⚠️ **`AI换脸` 的适用范围原文写的就是「视频深度合成技术」** → 类目表里唯一提到视频的**只有换脸**，不是「AI 视频生成」。全表检索 `音频/语音/声音/播放器` 命中为 0 |
| **文娱 - 其他视频** | 资质 6 选 1（含《信息网络传播视听节目许可证》） | 个体户拿不到其中任何一张 |
| **视频广场** | 要求**企业主体** + 视听节目备案 | 主体类型直接不满足 |
| **《信息网络传播视听节目许可证》** | 56 号令第八条(一)：「具备**法人资格**，为**国有独资或国有控股单位**」（该条**不按业务类别区分**，是全体申请人的基本条件）；另服务指南要求专业人员 20 人以上 | 对个体工商户是**结构性不可能**（无法人资格）；**民营公司同样过不去**（非国有）。注册资本 1000/2000 万只是 2008 年 44 号通知的审查口径，现行服务指南已不列 |
| AIGC 标识 | 视频同样需要显著标识，且「不可被截图裁掉」这条在动态内容上更难落地 | 需为视频单独设计角标 |

⚠️ **一条与视频无关、但被视频问出来的既有风险（现已核实到原文，结论比原来更明确）**：

1. **纯音频在法规定义里是明文纳入的**，不是"可能被主张"——《互联网等信息网络传播视听节目管理办法》（39 号令，未被 56 号令废止）第二条：视听节目指「由可连续运动的图像**或可连续收听的声音**组成的视音频节目」。**找不到任何把音频排除掉的文字。**
2. 辅证：总局《网络视听节目精品创作传播工程》扶持通知把「**网络音频节目**」与网络动画片、综艺、纪录片并列为网络视听节目形态；总局《信息网络传播视听节目许可证》**持证机构目录（截至 2025-07，约 399 家）里含上海喜马拉雅、阿基米德、库客音乐、酷狗**等纯音频起家的主体。→ 头部听书平台是**按视听节目持证经营**的。这是实践证据，⚠️ 但目录不披露各家许可项目类别，**不能当作规则依据**。
3. 仍然没有官方口径的，是那个真正决定我们命运的窄问题：**「一段 400 字、单次 AI 生成、免费、不开放上传的音频，是否构成『一个节目』」** ⏳。而且要说清两件事：**免费不构成豁免**（56 号令第二条只写"向公众提供"，无"经营/营利"限定），**不开放 UGC 也不豁免**（第二条把"自己制作编辑集成并向公众提供"和"为他人提供上载传播"写成**并列的两种情形**，我们是第一种）。

**所以「我只是生成音频也不行吗」的准确回答**：不是"也不行"，是**音频的敞口比视频更靠前、且砍不掉**——它先在**微信类目**这一关就可能卡住（类目表无语音子项，见 `docs/MVP排期.md` §6.1），再往法规那一关才轮到视听证的问题。两关的最坏结果也不同：类目卡住是「要求补交不出的材料 → 限期调整或下架」，视听证问题是「理论上无证经营 → 警告 + 3 万以下罚款」（罗湖案实罚 1 万）。**差别在于音频是产品本体，只能带着不确定性往前走；视频是可以砍掉的增量，所以在音频已有敞口时再往"更像视频节目"加码，是把同一个风险乘上倍数。**

## 5. 端侧：`<video>` 没有音频那套熄屏能力

| 能力 | `getBackgroundAudioManager`（现方案） | `<video>` |
|------|-----------------------------------|-----------|
| 熄屏继续 | ✅（配 `requiredBackgroundModes: ["audio"]`） | ❌ |
| 后台形态 | 系统锁屏控制条可播/停 | 仅**小窗（PiP）**，需要前台可见 |
| 默认自动播放 | 由我们控制 | `autoplay` 默认 false，需显式设置 |

**这与睡前场景正面冲突**：睡前故事的价值恰恰在「灯关了、手机扣过去、只剩声音」。加上视频后，熄屏即停 → 家长要么亮屏放着（更亮、更费电、更不像睡前），要么视频变成「孩子醒了看的另一个东西」——那是产品的重新定位，不是一个功能开关。

这条比成本、比证照都更早否定路线 D：**视频在当前场景里不改善体验，只增加约束。**

## 6. 如果仍要推进视频，先打两个电话

⚠️ **顺序提醒：这两通电话排在「音频类目落脚点」那两通之后**（见 `docs/主体与证照准备.md` §8 第 1、2 通）。音频是我们已经要付的确定性代价，视频只是往同一个方向加码——先问清手里这块地能不能站人，再问能不能加盖一层。

在写任何视频代码之前：

1. **微信侧**（小程序后台类目咨询 / 官方工单）：「个体工商户 + 已具备深度合成类目，新增 AI 生成视频功能，需要哪个子类目、什么材料？`AI 创作` 的文本资质能否覆盖视频？」——要书面答复。
2. **火山侧**：「Seedance 的**算法备案**（生成合成类）是否包含视频生成？能否在同一份合作协议里把视频算法名称/备案编号一并写入？」——若对方协议只写了文本/图像算法，视频这块就没有可提交的材料。

两个答复都为是 → 按路线 C 重开评估；任一为否 → 视频需求转成路线 B，或等主体升级成公司后再谈。

## 8. 一句话建议

**把「视频」这个词从需求里换成「画面会动」**——后者用 B 路线（对已审核配图做缓慢推拉 + 交叉淡入）就能拿到 80% 的睡前氛围收益，成本接近零，且不会把主体资格、类目、审核、熄屏体验四件事同时打开。真 AI 视频留到公司主体 + 收费形态定下来之后，作为独立版本评估。
