# 接口与数据

约定：`HTTPS + JSON`，域名走微信「服务器域名」白名单。所有响应带 `{code, message, data, traceId}`；`code=0` 成功。鉴权为登录时下发的短期 token（`Authorization: Bearer`），**openid 不出后端**。

> ⚠️ 标注「示意」的字段名是我按通用形态写的占位，火山 TTS/图像、内容安全的确切路径与字段以核实结果回填（见 §7）。后端要做供应商适配层隔离这些差异。

### 1.2 创建故事（发起生成）`POST /api/v1/stories`

```jsonc
// 请求
{
  "requestId": "c-9f2c7a10-6b3f-4e1a-9d84-2f1b7ac55e01",   // 客户端 UUID，幂等键
  "childId": "ch_1001",
  "input": "小兔子第一次自己睡觉",
  "durationLevel": "MEDIUM",        // SHORT 250字 / MEDIUM 450字 / LONG 700字
  "voiceCode": "girl_warm",         // girl_warm | grandpa_story | kid_peer
  "speed": 0.9,                     // 睡前默认略慢
  "withMoral": true,
  "bgm": "rain"                     // none | music_box | rain | white_noise
}

// 响应 202
{ "code": 0, "data": {
  "storyId": "st_20261102_00812",
  "status": "AUDITING",
  "quotaLeft": 2,
  "estimatedReadySeconds": 12
}}
```

**幂等**：同一 `requestId` 重复提交返回同一 `storyId` 且不扣额度；不同 `requestId` + 相同 input + 相同参数 → 生成**新内容**（LLM temperature 0.9，要求开头不同于该用户上一篇）。

### 1.3 生成进度 `GET /api/v1/stories/{storyId}/progress`

轮询 800ms（阶段变化时可缩短到 500ms）。

**流式方案的真实选项（已核实）**：`wx.request` 的 `enableChunked` 自基础库 **2.20.2** 起语义是「开启 transfer-encoding chunked」，配合 `RequestTask.onChunkReceived` 可逐块接收——**可以用来接收流式文本**，体验比轮询好（段一生成就显示）。但官方文档无「支持 SSE」字样，不要按 SSE 实现。
取舍：**M2 先用轮询打通（稳、简单、后端无长连接管理）**，M3 若首字可见时长不达 4s 目标，再把 `POST /stories` 改成 chunked 流式。**两个坑**：①官方原文「进入后台运行后，如果 5s 内网络请求没有结束，会回调错误信息」→ 家长在生成中锁屏，轮询/流式都会失败，必须 `onShow` 时重新拉 `progress` 恢复；②`wx.request` 最大并发 10、`connectSocket` 最大并发 5，默认超时 **60s**（不要依赖默认值，显式设 `timeout`）。

| 方法 | 路径 | 说明 |

| `GET` | `/api/v1/me` | 额度、默认参数、孩子列表 |

**错误码**

| code | 含义 | 前端文案 |
|------|------|----------|
| `40010` | 输入未通过审核 | 这句话我们讲不了，换一个试试 |
| `40011` | 生成内容未通过审核 | 这个故事不太合适，换一个想法？ |
| `40020` | 今日额度用尽 | 今天讲完啦，明天再来 |
| `40021` | 并发超限（已有进行中的故事） | 上一个还在编，稍等一下 |
| `42900` | 平台日总额熔断（成本保护） | 今晚的小朋友太多啦，稍后再试 |
| `50010` | LLM/TTS 供应商不可用（主备均失败） | 准备故事的时候打了个盹，再试一次 |

## 3. 后端 → TTS（火山引擎豆包语音，已核实）

### 3.1 接口形态（⚠️ 硬约束）

- 当前推荐：`POST https://openspeech.bytedance.com/api/v3/tts/unidirectional` —— **单向流式**，一次性提交全文，**HTTP Chunked 流式返回二进制音频**（mp3/pcm/wav/ogg_opus），**不返回 URL**。
- 鉴权：header `X-Api-Key` + 必带 `X-Api-Resource-Id`（示例取值 `seed-tts-2.0` / `seed-icl-2.0`）。新版不需要 `X-Api-Cluster`。
- 旧的一次性非流式接口 `/api/v1/tts` 官方已标「不推荐」，且其文本上限是 **1024 字节**——注意 450 个汉字 UTF-8 约 1350 字节，**超限**。v3 的确切上限官方页未明示。

**由此产生的后端必备一层（不可省）**：

```
chunked 二进制聚合 → 完整 mp3 →（混 BGM）→ 写 AI 生成元数据 → 转存 OSS → 生成签名 URL → 下发小程序
```

⚠️ **「写 AI 生成元数据」这一步是法定动作，不是可选优化**（《人工智能生成合成内容标识办法》第五条，2025-09-01 施行，原文：「在生成合成内容的**文件元数据**中添加**隐式标识**，隐式标识包含**生成合成内容属性信息、服务提供者名称或者编码、内容编号**等制作要素信息」）。这条**不给二选一**，与显式标识不同（显式那半条第四条(二) 允许「在交互场景界面中添加显著的提示标识」替代，即 P3 的常驻小字就够，**不必在音频里插一句口水音**）。

落到实现：混音之后、转存之前用 ffmpeg 写 ID3v2 TXXX 帧（`Comment(arts)` 一帧不够，按要素拆开），例如

```bash
ffmpeg -i merged.mp3 -c copy \
  -metadata Comment="AI_GENERATED" \
  -metadata Artist_Code="volcengine-doubao-tts" \
  -metadata Content_ID="<storyId>:<segmentSeq>" \
  -metadata Provider="merchant:<统一社会信用代码>" labeled.mp3
```

`Content_ID` 与 `t_story_audio` 对得上，微信审核抽查时能自证。**验收清单第 30 条就是抽查线上 OSS 上的 mp3 元数据三要素齐全**。注意 `t_story_audio.timestamp_source` 旁边要再加 `label_written`（见 §6），否则无法区分「历史未写标文件」与「新写入文件」。

小程序端 `InnerAudioContext` / `BackgroundAudioManager` 不能消费 chunked 二进制，所以**必须由后端聚合成完整文件**。好消息：这样也天然解决了「音频要落自己存储」的问题，不存在供应商临时链接过期的风险。

**分段提交的坑（要提前设计）**：若 v3 上限确实容不下 700 字长档，需把整篇切成 2-3 次请求再拼接音频。此时时间戳必须**累加前序片段时长**，否则高亮会从第二段开始错位。句级时间戳聚合逻辑见 §3.3。

### 3.2 时间戳与音色（已核实，比预期好）

- **支持逐字时间戳**：请求参数 `with_timestamp`（配合 `with_frontend`）；返回 `utterances[].words[]`，单元是**单字**，形如
  `{"word":"你","startTime":0.195,"endTime":0.335,"confidence":0.89}`，外层另有 `duration`、`frontend`。
  ⚠️ `startTime/endTime` 单位是**秒（浮点）**，落库前 ×1000 转 ms。
- **儿童音色存在**：音色列表含「**儿童绘本 2.0**」类（中文，支持语速/音量/音高）——正是睡前故事场景；豆包语音 2.0 系列部分支持多情感与 SSML。精确 speaker id 全表与逐条能力标注待补。
- 睡前场景做法：选「儿童绘本」类音色 + 调低 `speech_rate`（对应 §1.1 的 `speed=0.9`）。

### 3.3 请求/响应示意

```jsonc
// 请求（v3 unidirectional）
{ "text": "<整篇文本>",
  "speaker": "<儿童绘本类音色 id>",
  "speed_ratio": 0.9, "volume": 0.8,
  "with_timestamp": true, "with_frontend": true,
  "format": "mp3", "sample_rate": 24000 }

// 流式响应：二进制音频 chunk(s) + 附带的时间戳 JSON 帧（示意，聚合后）
{ "words": [ { "word": "兔", "startTime": 0.320, "endTime": 0.520 }, … ],
  "duration": 302.4 }
```

**句级时间戳由后端派生**（不做逐字高亮，见 README §6.2）：取每句首字的 `startTime×1000` 为 `startMs`，末字 `endTime×1000` 为 `endMs`；分段提交时逐段累加 `duration` 作为偏移。这样 §1.3 下发给前端的 `sentences[]` 结构不变。

**兜底**：若时间戳缺失/置信度低/分段偏移不可信，按「句字数 ÷ 总字数 × 总时长」估算，`audio.timestampSource` 标记为 `ESTIMATED`，便于观测高亮观感。若 TTS 全挂 → 返回无 `audio` 的纯阅读模式。

## 4. 后端 → 图像生成（火山方舟 Seedream，已核实）

- 模型：方舟 Seedream 系列（`doubao-seedream-5.0` / `4.0` 等，另有 5.0 pro/flash/lite、4.5）。
- 接口：`POST /api/v3/images/generations`，鉴权 Bearer API Key。
- **角色一致性有官方机制**：参数 `image`（URL 或 base64），主体一致性由模型提供；参考图上限 **5.0 pro 最多 10 张、4.0 最多 14 张**。→ 绘本「每段小兔子长得一样」这条硬需求**可以真正满足**，不必靠 prompt 复述。
- 尺寸：`size` 支持 1K-4K 档位，宽高比范围 `[1/16, 16]` → **3:4 竖版绘本页可行**，无需后期裁切。
- 未核实：单次生成耗时量级、每档公开单价（价格页动态渲染未取到）。

```jsonc
// 请求（段 2，带段 1 定妆图作角色参考）
{ "model": "doubao-seedream-4.0",
  "prompt": "绘本插画风格。白色小兔子，长耳朵尖有一点灰，系蓝色小围巾，
             抱蓝色小毯子坐在床上，房间昏暗，窗外一弯月亮，柔和暖色调。
             3:4 竖版，画面内不出现任何文字，无水印。",
  "size": "1K", "aspect_ratio": "3:4",
  "image": [ "<段1定妆图的 OSS 签名 URL 或 base64>" ] }

// 响应
{ "data": [ { "url": "https://…/tmp/xxx.png", "expires_in": 86400 } ] }
```

**策略**：段 1 先生成（含 `characterAnchor`）→ 转存 OSS → 作为段 2-6 的 `image` 参考 → 段 2-6 并行。所有 URL **必须转存**（火山返回的是临时链接，会过期）。每段最多重试 1 次，失败即 `imageStatus=FAILED`，前端占位卡，**不阻塞音频就绪**。

**降级开关（成本用）**：`imageCount = 1 | 3 | 全段`。若核实后单图价格使图片成本远高于语音+文字，首版只出「1 张封面 + 段 1/段 末 共 3 张」，中间段复用背景模板。

## 5. 内容安全（接口与额度已核实，含一条设计修正）

微信官方 sec-center 现列三个接口：`msgSecCheck`、`mediaCheckAsync`、`getuserriskrank`。**未找到**区分「用户输入」与「AI 生成」的专用接口——AIGC 文本同样走 `msgSecCheck`。

| 环节 | 接口 | 关键限制（官方原文数值） | 同步性 |
|------|------|------------------------|--------|
| 输入一句话 | `POST /wxa/msg_sec_check`（`version=2`，`scene` 仅 1-4） | 文本**≤2500 字**；4000 次/分钟、200 万次/天、**未上架小程序 100 次/天**；须传**近两小时内访问过小程序的 openid** | **同步**，返回 `result.pass / risky` + `suggest` |
| 生成文本（标题+段落+moral） | 同上 | 450-700 字远低于 2500 字上限，一次请求送全文 | **同步** |
| 生成图片 | `POST /wxa/media_check_async` | 图/音均可；**单文件 ≤10M**；2000 次/分钟、20 万次/天；**结果异步，30 分钟内事件推送** | ⚠️ **异步** |
| 兜底 | 旧同步 `imgSecCheck` | 官方公告称「2.0 版本暂不支持同步，可使用 1.0 版本的 `imgSecCheck`」 | 同步（能力较弱，作可选前置闸） |

### 5.1 图片审核必须改成「双层」（原同步方案不成立）

因为 `mediaCheckAsync` 是异步回调，**不能在生成时同步拿到微信侧的结论再决定是否展示**。落地方案：

1. **同步闸门 = 供应商侧**：火山方舟返回的 `OutputImageSensitiveContentDetected` / `InputImageSensitiveContentDetected` 是同步 HTTP 400，用它做**展示前的拦截**（重试 1 次 → 占位卡）。
2. **异步复核 = 微信侧**：图片落 OSS 后立即提交 `mediaCheckAsync`，收到事件推送若判危 → 标记该段 `imageStatus=RECALLED`，`imageUrl` 置空降级为占位卡，并把整篇故事标 `risk_flag` 不再进任何列表推荐；同时写 `t_audit_log` 留证。
4. **家长侧提示文案统一为**「这个故事不太合适，换一个试试」，**不透露命中内容**（审核规则本身不可外泄）。
5. **要新增一个公开回调端点**：`mediaCheckAsync` 的结果通过微信「消息与事件接收」推送，后端需实现 URL 校验（GET 签名）+ 事件接收（`wxa_media_check`），按 `trace_id` 回写 `t_story_segment.image_status`。这是全项目唯一一个由外部主动 POST 进来的入口，要做签名校验与幂等。
6. **合规留证**：审核记录、AIGC 标识截图、类目资质材料留档 ≥ 6 个月，便于申诉与复核。

文本审核保持同步（`msgSecCheck` 同步返回），所以输入与输出文本可以真正「不过就不给看」。

### 5.2 AIGC 标识（官方类目表备注原文要求）

> 「所有人工智能生成合成内容，如：AI问答、AI换脸、AI绘画、AI创作类目等类型，需在 AI 生成内容显著位置进行标注，如：明确标注为'AI生成、人工智能生成'或同等含义字样」

我的写法是「故事与插图由 AI 生成」，属「同等含义」；**为降低驳回概率，建议原文里同时出现「AI生成」四字**，例如播放页副标题下 `内容由AI生成 · 故事与插图均为人工智能生成`。标识不可折叠、不可被分享文案裁掉。

标识义务不止微信这一层，**《人工智能生成合成内容标识办法》（国信办通字〔2025〕2 号，2025-09-01 施行）是按形态分别规定的**：

| 形态 | 条文 | 我们的做法 |
|------|------|-----------|
| 文本 | 第四条(一)：起始/末尾/中间加文字或符号提示，**或**交互界面显著提示 | 生成结果页与 P3 常驻小字（走「或者」后半段） |
| **音频** | 第四条(二)：起始/末尾/中间加**语音提示或音频节奏提示**，**或**交互场景界面显著提示 | ✅ **走「或者」后半段**——界面提示即可，**不在 mp3 里插口水音**（睡前场景那一声是破坏性的） |
| 图片 | 第四条(三)：适当位置显著提示 | 图片右下角角标或段下说明 |
| 视频 | 第四条(四)：起始画面 + 播放周边 | 首版无视频，见 `docs/视频形态评估.md` |
| **全部形态** | **第五条：文件元数据加隐式标识**（属性信息 + 服务提供者名称或编码 + 内容编号），**无「或者」** | ⚠️ **必须实现**，见 §3.1 的 ffmpeg 步骤 |

三条附随义务别漏：
- 第四条末句：提供**下载、复制、导出**时须确保**文件内含显式标识** → 所以**首版不做音频导出**（已写进 Won't），做了就得把提示嵌进音频本体。
- 第八条：要在**用户服务协议**里说明标识的方法与样式 → 用户协议需要专门一段。
- 第七条：**应用分发平台（即微信审核）会核验标识材料** → 这不是纸面自律，是会被查的。
- 第十条：禁止恶意删改、隐匿标识；另《深度合成规定》第十九条要求在**网站/应用显著位置公示**算法备案号（我们走「调用已备案模型 → 登记」路线，见 §7 与 `docs/主体与证照准备.md`）。

### 5.3 审核接口不可用时的行为

`msgSecCheck` 调用失败（非 0 码）→ **默认拒绝**并返回 `50010`，绝不放行未审内容。运营侧加一条告警：单日审核失败率 > 1% 触发。

### 5.4 一条会直接被拒的技术条款（与产品机制冲突，已改设计）

《常见拒绝情形》**3.5.2** 原文：「**禁止视频、音乐、语音等多媒体的自动播放**」。

- ❌ 原设计「音频就绪即播」不合规 → ✅ 改为就绪后跳 P3 并**停在待点播放键**（`docs/页面与交互.md` P2/P3）。
- ❌ 段与段之间、重播、`onShow` 回到前台都**不得自动起播**。
- 后端不受影响；只是前端 `BackgroundAudioManager.play()` 的调用点必须全部由用户点击触发（`getBackgroundAudioManager` 本身仍可用，熄屏连续播放靠它，见 §3）。
- ⚠️ 不要用「延迟 100ms 触发」「伪装成点击」等做法绕过——运营规范 **2.5.19**「绕开、对抗审核机制」最重可到永久下架。

## 6. 数据模型（MySQL 8，DDL 摘要）

```sql
-- 家长账号（不存儿童真实信息）
CREATE TABLE t_user (
  id VARCHAR(32) PRIMARY KEY, open_id VARCHAR(64) NOT NULL UNIQUE,
  union_id VARCHAR(64) NULL, nickname VARCHAR(64) NULL,
  default_voice VARCHAR(20) DEFAULT 'girl_warm',
  default_bgm VARCHAR(20) DEFAULT 'rain',
  dark_mode TINYINT DEFAULT 1, created_at DATETIME NOT NULL);

-- 孩子档案：只存小名与年龄档
CREATE TABLE t_child (
  id VARCHAR(32) PRIMARY KEY, user_id VARCHAR(32) NOT NULL,
  alias VARCHAR(32) NOT NULL,        -- 「乐乐」，非真实姓名
  age_band VARCHAR(10) NOT NULL,     -- 5_7
  story_count INT DEFAULT 0,         -- 系列计数「第 N 个故事」
  created_at DATETIME NOT NULL, INDEX idx_child_user(user_id));

CREATE TABLE t_story (
  id VARCHAR(32) PRIMARY KEY,
  request_id VARCHAR(64) NOT NULL UNIQUE,       -- 幂等
  user_id VARCHAR(32) NOT NULL, child_id VARCHAR(32) NOT NULL,
  input_text VARCHAR(120) NOT NULL, input_audit_result VARCHAR(16) NOT NULL,
  title VARCHAR(64), character_anchor VARCHAR(200),
  duration_level VARCHAR(10) NOT NULL, voice_code VARCHAR(20) NOT NULL,
  speed DECIMAL(3,2) NOT NULL DEFAULT 0.90, with_moral TINYINT NOT NULL DEFAULT 1,
  bgm VARCHAR(20), moral VARCHAR(120),
  word_count INT, segment_count TINYINT,
  status VARCHAR(24) NOT NULL,      -- AUDITING/GENERATING_TEXT/GENERATING_IMAGE/SYNTHESIZING_AUDIO/READY/FAILED/CANCELED
  fail_code INT, fail_reason VARCHAR(200),
  risk_flag TINYINT NOT NULL DEFAULT 0,   -- 微信 mediaCheckAsync 异步复核判危后置 1：图片撤回、不进任何列表
  audit_text_pass TINYINT NOT NULL DEFAULT 0,  -- msgSecCheck 通过标记（未通过不允许变 READY）
  llm_provider VARCHAR(24), series_no INT,      -- 第 N 个故事
  favorite TINYINT DEFAULT 0, deleted_at DATETIME NULL,
  created_at DATETIME NOT NULL, updated_at DATETIME NOT NULL,
  INDEX idx_story_user_created(user_id, created_at), INDEX idx_story_child(child_id, series_no));

-- 段落：文本 + 图
CREATE TABLE t_story_segment (
  id BIGINT AUTO_INCREMENT PRIMARY KEY, story_id VARCHAR(32) NOT NULL,
  seq TINYINT NOT NULL, body VARCHAR(400) NOT NULL,
  image_object_key VARCHAR(200),
  image_status VARCHAR(16) NOT NULL DEFAULT 'PENDING',  -- PENDING/READY/FAILED/RECALLED(异步复核撤回)
  wx_trace_id VARCHAR(64) NULL,      -- mediaCheckAsync 返回的 trace_id，回调时对回本行
  created_at DATETIME NOT NULL, updated_at DATETIME NOT NULL,
  UNIQUE KEY uk_seg(story_id, seq), INDEX idx_seg_trace(wx_trace_id));

-- 音频 + 句级时间戳（同文本不同语速各一行）
CREATE TABLE t_story_audio (
  id BIGINT AUTO_INCREMENT PRIMARY KEY, story_id VARCHAR(32) NOT NULL,
  voice_code VARCHAR(20) NOT NULL, speed DECIMAL(3,2) NOT NULL,
  text_md5 CHAR(32) NOT NULL,                 -- 与 (voice,speed) 组合作复用键
  provider VARCHAR(24) NOT NULL, audio_object_key VARCHAR(200) NOT NULL,
  duration_ms INT NOT NULL, size_bytes INT, format VARCHAR(10) DEFAULT 'mp3',
  timestamp_source VARCHAR(16) NOT NULL,      -- PROVIDER | ESTIMATED
  label_written TINYINT NOT NULL DEFAULT 0,   -- 第五条隐式标识是否已写入文件元数据(0=未写/1=已写)
  content_id VARCHAR(64) NULL,                -- 写进元数据的「内容编号」，与 audio_object_key 一一对应，供审核抽查回表
  sentence_json JSON NOT NULL,                -- [{index,segmentSeq,text,startMs,endMs}]
  created_at DATETIME NOT NULL,
  INDEX idx_audio_reuse(text_md5, voice_code, speed));

-- 额度（日）
CREATE TABLE t_quota (
  id BIGINT AUTO_INCREMENT PRIMARY KEY, user_id VARCHAR(32) NOT NULL,
  day DATE NOT NULL, used INT NOT NULL DEFAULT 0, daily_limit INT NOT NULL DEFAULT 3,
  UNIQUE KEY uk_quota(user_id, day));

-- 平台日成本熔断
CREATE TABLE t_cost_daily (
  day DATE PRIMARY KEY, story_count INT DEFAULT 0, cost_cent BIGINT DEFAULT 0,
  llm_cost_cent BIGINT DEFAULT 0, tts_cost_cent BIGINT DEFAULT 0, img_cost_cent BIGINT DEFAULT 0,
  fuse_triggered TINYINT DEFAULT 0);

-- 供应商调用流水（观测与对账）
CREATE TABLE t_provider_call (
  id BIGINT AUTO_INCREMENT PRIMARY KEY, trace_id VARCHAR(64) NOT NULL,
  story_id VARCHAR(32), provider VARCHAR(24) NOT NULL, api VARCHAR(40) NOT NULL,
  status VARCHAR(16) NOT NULL, http_code INT, ms_cost INT,
  tokens_in INT, tokens_out INT, chars INT, images INT,
  cost_cent INT, error_code VARCHAR(32), error_msg VARCHAR(200),
  created_at DATETIME NOT NULL, INDEX idx_pc_day(created_at), INDEX idx_pc_story(story_id));

-- 审核日志（合规留证）
CREATE TABLE t_audit_log (
  id BIGINT AUTO_INCREMENT PRIMARY KEY, biz_type VARCHAR(16) NOT NULL,  -- INPUT_TEXT/GEN_TEXT/GEN_IMAGE
  biz_id VARCHAR(64) NOT NULL, provider VARCHAR(24) NOT NULL,
  result VARCHAR(16) NOT NULL, hit_label VARCHAR(64), raw_json JSON,
  created_at DATETIME NOT NULL, INDEX idx_audit_biz(biz_type, biz_id));
```

**关键约束**

- `t_story.request_id` 唯一 = 幂等的实现处。
- 音频按 `(text_md5, voice_code, speed)` 复用，重试与「换个语速」不产生重复合成成本。
- 对象存储 key 存库，URL 由后端签临时凭证下发（默认 1h）；`favorite=1` 的 story 免于回收任务。
- **不建**任何儿童真实身份字段（姓名、生日、学校、人脸）——这是合规底线也是数据红线。
